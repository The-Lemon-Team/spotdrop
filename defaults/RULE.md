# Спецификация и правила структуры профилей в папке defaults

Документ регламентирует правила организации и добавления профилей музыкальной библиотеки для **Bandita Player** (Android Native & Web).

---

## 1. Назначение папки `defaults`

Папка `defaults/` является центральным хранилищем профилей по умолчанию и предустановленных коллекций музыки.

В перспективе через данную директорию можно добавлять неограниченное число профилей (например: жанровые подборки, коллекции под настроение, библиотеки разных пользователей или демо-подборки).

---

## 2. Общая структура каталога

```text
defaults/
├── RULE.md                          # Настоящий документ с правилами и спецификацией
├── RULE.txt                         # Текстовая версия правил
├── default/                         # Основной дефолтный профиль
│   ├── profile.json                 # Метаданные профиля (название, emoji, id)
│   ├── YourLibrary.json             # (Опционально) Сохраненные треки из Spotify
│   └── Playlist1.json               # (Опционально) Плейлисты из Spotify
├── template/                        # Эталонный шаблон для создания нового профиля
│   ├── profile.json                 # Шаблон метаданных
│   ├── YourLibrary.example.json     # Пример структуры библиотеки
│   └── Playlist1.example.json       # Пример структуры плейлистов
└── <custom_profile_name>/           # Будущие профили (создаются по правилу ниже)
    ├── profile.json                 # Метаданные нового профиля
    ├── YourLibrary.json             # (Опционально)
    └── Playlist1.json               # (Опционально)
```

---

## 3. Правило формирования папки профиля

Каждый профиль представляет собой отдельную подпапку внутри `defaults/`.

### 3.1. Именование папки
- Имя папки должно быть в нижнем регистре (slug format).
- Допустимые символы: латинские буквы (`a-z`), цифры (`0-9`), дефис (`-`) и знак подчеркивания (`_`).
- Пробелы и спецсимволы не допускаются.
- Примеры корректных имен:
  - `default`
  - `cyberpunk_vibes`
  - `chillout-lounge`
  - `rock_classics`
  - `workout_2026`

### 3.2. Состав файлов внутри папки профиля

| Файл | Обязательность | Назначение |
| :--- | :--- | :--- |
| `profile.json` | **Рекомендуется** | Метаданные профиля (отображаемое имя, ID, аватар, цвет). При отсутствии имя профиля генерируется из названия папки. |
| `YourLibrary.json` | **ОПЦИОНАЛЬНО** | Экспорт «Любимые треки» (Liked Songs) из Spotify. |
| `Playlist1.json` | **ОПЦИОНАЛЬНО** | Экспорт плейлистов с треками из Spotify. |

> **ВАЖНО (Принцип опциональности):**  
> Файлы Spotify (`YourLibrary.json`, `Playlist1.json`) являются **строго опциональными**.  
> Профиль считается полностью валидным в любом из следующих вариантов:
> 1. Только `profile.json` (пустой профиль, готовый к ручному наполнению пользователем через UI).
> 2. `profile.json` + только `YourLibrary.json` (только лайкнутые треки).
> 3. `profile.json` + только `Playlist1.json` (только плейлисты).
> 4. `profile.json` + `YourLibrary.json` + `Playlist1.json` (полный комплект).

## 4. Спецификация форматов файлов

### 4.1. Спецификация `profile.json`

Файл содержит информацию о профиле для интерфейса плеера:

```json
{
  "id": "profile_unique_id",
  "name": "Название Профиля",
  "avatarEmoji": "🎧",
  "description": "Краткое описание коллекции",
  "isDefault": false,
  "themeColor": "#00E5FF"
}
```

#### Описание полей:
- `id` *(string, обязательно)*: Уникальный идентификатор профиля. Рекомендуется префикс `profile_`, например: `profile_rock`.
- `name` *(string, обязательно)*: Человекочитаемое имя профиля, отображаемое в шапке плеера и модальном окне переключения.
- `avatarEmoji` *(string, опционально)*: Один эмодзи символ для аватара профиля (по умолчанию: `🎧`).
- `description` *(string, опционально)*: Краткое описание подборки.
- `isDefault` *(boolean, опционально)*: `true` только для основного стартового профиля, для остальных `false`.
- `themeColor` *(string, опционально)*: Акцентный HEX-цвет профиля в палитре плеера.

---

### 4.2. Спецификация `YourLibrary.json` (Spotify Saved Tracks)

Стандартный формат экспорта сохраненных треков Spotify (JSON):

```json
{
  "tracks": [
    {
      "artist": "Имя исполнителя",
      "album": "Название альбома",
      "track": "Название трека",
      "uri": "spotify:track:xxxxxxxxxxxxxxxxxxxxxx"
    }
  ]
}
```

#### Правила импорта плеером:
- Каждый элемент преобразуется в каноническую ячейку `TrackCell`.
- Автоматически присваиваются теги:
  - `#all` — для включения в общий список.
  - `#library` — пометка сохраненных треков.
  - `#<исполнитель>` — тег исполнителя для быстрой группировки.
- Если трек уже был добавлен через плейлист, его теги объединяются без дублирования.

---

### 4.3. Спецификация `Playlist1.json` (Spotify Playlists)

Стандартный формат экспорта плейлистов Spotify (JSON):

```json
{
  "playlists": [
    {
      "name": "Название Плейлиста",
      "lastModifiedDate": "YYYY-MM-DD",
      "items": [
        {
          "track": {
            "trackName": "Название трека",
            "artistName": "Имя исполнителя",
            "albumName": "Название альбома",
            "trackUri": "spotify:track:xxxxxxxxxxxxxxxxxxxxxx"
          },
          "addedDate": "YYYY-MM-DD"
        }
      ]
    }
  ]
}
```

#### Правила импорта плеером:
- Название каждого плейлиста нормализуется в хэштег плеера (например, `"Summer Chill 2024"` $\rightarrow$ `#summer`).
- Все треки внутри плейлиста получают соответствующий `#тег`.
- На главном экране создаются чипы фильтрации для каждого плейлиста.

## 5. Пошаговая инструкция: как добавить новый профиль

Чтобы добавить новый профиль через папку `defaults/`:

1. **Создайте новую папку** внутри `defaults/`:
   ```bash
   defaults/synthwave_80s/
   ```

2. **Создайте файл `profile.json`** (можно скопировать из `defaults/template/profile.json`):
   ```json
   {
     "id": "profile_synthwave",
     "name": "Synthwave 80s",
     "avatarEmoji": "🌆",
     "description": "Retrowave, synthwave and cyberpunk music collection",
     "isDefault": false
   }
   ```

3. **(Опционально) Добавьте экспортированные файлы Spotify**:
   - Поместите `YourLibrary.json` и/или `Playlist1.json` внутрь папки профиля `defaults/synthwave_80s/`.
   - Если файлов нет — профиль будет создан пустым и готов к привязке файлов через интерфейс плеера на лету.

4. **Готово!** Плеер автоматически обнаружит папку профиля при синхронизации ассетов.

---

## 6. Принцип отказоустойчивости и опциональности

1. **Отсутствие файлов не ломает сборку и запуск:**
   Ни Android-приложение, ни Web-версия не зависят от обязательного наличия JSON-файлов при компиляции.
2. **Пустая библиотека:**
   Если в профиле нет треков, плеер отображает дружелюбный экран Empty State с кнопкой перехода в профили и привязки файла.
3. **Безопасный парсинг:**
   Парсер плеера защищен от отсутствующих ключей, пустых массивов и поврежденных JSON файлов, пропуская некорректные записи без падения приложения.
